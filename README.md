# MONO — youtube → audio

Локальный аудио-плеер для YouTube: без регистрации, без скачивания файлов —
только живая звуковая дорожка. Заточен под музыку для работы: minimal techno, deep house.

## Запуск

```bash
brew install yt-dlp        # единственная внешняя зависимость
node server.js             # → http://localhost:8787
```

Требуется Node ≥ 22.5 (используется встроенный `node:sqlite`). npm-зависимостей нет.

## Что умеет

- **Поиск** по YouTube без API-ключа (через yt-dlp)
- **Жанры** — пресеты запросов: minimal techno, deep house, dub techno, melodic, ambient…
- **Подписки** без аккаунта — на каналы (`@хендл`, ссылка, даже ссылка на видео) и плейлисты.
  Хранятся локально в SQLite (`data/mono.db`)
- **Новинки** — агрегированная RSS-лента подписок
- **Плеер**: очередь из любого списка, перемотка (Range-прокси), shuffle,
  медиа-клавиши (MediaSession), визуализатор
- **Горячие клавиши**: `Space` — пауза, `←/→` — ±10 сек, `N/P` — трек назад/вперёд, `L` не вынесен — лайк кнопкой ♡

## Как это работает (и что НЕ делает)

- Ничего **не скачивается**: сервер берёт у YouTube прямую ссылку на аудио-формат
  (предпочитает `m4a`/AAC — играет во всех браузерах) и проксирует её в браузер на лету.
- На диске хранится только служебная мелочь: подписки, лайки, история — один файл `data/mono.db`.
- Ссылки на поток живут ~6 часов, поэтому они кэшируются на 2.5 часа
  и автоматически обновляются при 403.

## Если YouTube флагнул IP (бот-проверка «Sign in to confirm…»)

Симптом: поиск и RSS работают, а воспроизведение падает. YouTube заблокировал
player-API для этого IP. Что помогает:

1. **Подождать** — флаг обычно спадает сам за несколько часов
2. **Сменить сеть** — мобильная раздача с телефона, VPN. Быстрая диагностика:
   если с раздачи играет, а с домашней сети нет — дело в IP
3. **PO-токены** (уже настроено в этом проекте): плагин `bgutil-ytdlp-pot-provider`
   в `~/.yt-dlp/plugins`, локальный провайдер на Node в `~/bgutil-ytdlp-pot-provider/server`
   — server.js запускает его сам при старте (`127.0.0.1:4416`). Токены нужны
   для связки с клиентом `mweb` (прописан в `lib/yt.js`)
4. **Куки браузера** — см. раздел ниже

Важно: ссылки googlevideo привязаны к IP резолва — если пускаешь трафик через
прокси/VPN, стрим должен идти через тот же выходной IP, что и резолв.

## Куки (когда YouTube включает бот-проверку)

Если при воспроизведении видна ошибка «бот-проверка» — YouTube флагнул IP
(поиск при этом обычно работает). Лечение: отдать yt-dlp куки обычного браузера,
тогда запросы выглядят как твой обычный сёрфинг. Плеер ищет их сам, в таком порядке:

1. `MONO_COOKIES=chrome node server.js` (или `safari`, `firefox`, `edge`, `brave`,
   или путь к файлу) — явное указание
2. `cookies.txt` в корне проекта или в `data/` — экспорт из любого браузера
   (расширение «Get cookies.txt LOCALLY», открыть youtube.com → экспорт)
3. Safari, Chrome, Firefox, Edge, Brave — профили, установленные на этой машине

Для Safari на macOS нужно дать терминалу (приложению, из которого запущен плеер)
**Full Disk Access**: Настройки → Конфиденциальность и безопасность → Full Disk Access.
Проверка ленивая — доступ появился, через минуту подхватится без перезапуска.

Текущее состояние: `curl localhost:8787/api/status` → поле `cookies`.

## Структура

```
server.js        — HTTP-сервер: API, прокси аудио, статика
lib/yt.js        — обёртка yt-dlp (поиск / списки / резолв) + кэш
lib/db.js        — SQLite (подписки, лайки, история)
public/          — фронтенд без сборки: index.html, app.js, style.css
data/mono.db     — локальные данные (создаётся сам)
```

## Заметки

- Порт меняется через `PORT=8888 node server.js`.
- Путь к бинарнику: `YTDLP=/path/to/yt-dlp node server.js`.
- Личное использование. Соблюайте ToS YouTube: приложение стримит, а не копирует контент.
